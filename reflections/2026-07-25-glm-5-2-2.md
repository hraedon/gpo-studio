## On the project

The frozen-dataclass + JSON-snapshot-store + optimistic-concurrency
architecture is holding up remarkably well as features accumulate. Each
new capability (ADMX parsing, settings browser, Starter GPO lifecycle, AD
discovery) slots into the same pattern without requiring architectural
changes. The `assert_never` charter rule continues to pay dividends — it
caught no new bugs this session (the parsers already validate at parse
time), but the guarantee that every closed-set dispatch is exhaustive is
load-bearing for confidence.

The lab verification was the single highest-value activity. Testing the
parser against 223 real Microsoft ADMX files found 4 bugs that 1536
synthetic tests missed — including a P0 where 201 `supportedOn` definitions
were silently lost because the parser didn't descend into the
`<definitions>` wrapper. This reinforces a pattern: synthetic tests prove
the code handles what you thought of; real corpora prove it handles what
actually exists. The project should invest in more real-data verification.

The subagent-driven workflow was effective for plan-driven work. Each
tranche had a clear scope, the implementer agents followed conventions
well, and alternating adversarial (nemotron) and implementer (glm) reviewers
caught real issues without burning adversarial budget on every pass. The
most productive review was the lab verification report itself — it found
more bugs than any code review could have.

## On the work done

**Confident in:**
- The parser bug fixes — all four were confirmed against the real corpus
  after fixing, with zero errors across 3,532 Microsoft + 1,178 vendor
  policies. The fixes are small and localized.
- The `delete_starter_gpo` audit trail — the `deletion_log` table +
  v1→v2 migration is the right approach (tombstone revisions can't survive
  cascade delete). The adversarial reviewer confirmed transaction atomicity.
- The bulk action single-request fix — eliminates the partial-update risk
  by sending per-policy sides in one atomic call. The store's
  `bulk_replace_settings_by_prefix` already validated all settings in one
  transaction.
- The LDAP lab verification — `cred:ldap-bind` + `ldap3` in a temp venv
  proved the AD queries return correct data (27 OUs, 12 GPOs, principals
  with GUIDs/SIDs). The data structures match the model types.

**Less confident in:**
- The PowerShell discovery scripts in `ad_discovery.py` are syntactically
  tested (the tests check that the script text contains the right
  cmdlets/patterns) but have NOT been execution-verified on Windows. The
  SSH session to `mvmcitest01` couldn't pass through Windows domain
  credentials for `System.DirectoryServices`, and `System.DirectoryServices`
  isn't supported on Linux PowerShell Core. The LDAP verification via
  `ldap3` proved the underlying queries work, but the PowerShell scripts
  themselves need end-to-end testing on a Windows machine with domain
  credentials. This is the biggest unverified gap.
- The gPLink parsing fix (regex matches instead of split) is correct in
  principle but hasn't been tested with real multi-link gPLink data from
  the lab (the lab OUs do have gPLinks, but the parsing happens in the
  PowerShell script on Windows, not in Python).
- The AD discovery module is new code with 52 tests but hasn't been
  exercised through the full generate→run→import pipeline against real AD.
  The API endpoints are tested with TestClient but not with real discovery
  JSON from a live AD.
