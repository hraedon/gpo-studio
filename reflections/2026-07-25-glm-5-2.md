## On the project

GPO Studio is maturing into a real authoring workbench. The core
architecture — frozen dataclasses, JSON-snapshot store, optimistic
concurrency, deterministic PReg — is holding up well as features
accumulate. The settings_browser reverse-index is the right abstraction:
it bridges raw registry tuples and human-facing ADMX policy identity
without polluting either layer.

The subagent-driven workflow was effective for this kind of plan-driven
work. Each tranche had a clear scope, the implementer agents followed
the codebase conventions well, and the adversarial reviewers caught real
issues (the export.py wildcard + validator gap was the most important).
The false positives (prefix collision, ValidationError handling) were
worth verifying rather than dismissing — confirming them built
confidence in the implementation.

The amount of uncommitted prior-session work (WP-2 template_store,
provenance, scripts, docs) was surprising — 37 files changed total, many
from sessions that never committed. This made the diff noisy and the
adversarial review broader than necessary. The project would benefit
from more frequent commits.

## On the work done

**Confident in:**
- The export.py fix and plan validator update — the wildcard behavior
  was confirmed broken via lab verification (mvmcitest01), and the
  fix generates valid PowerShell that passes the validator.
- The Starter GPO lifecycle — the model is minimal (two fields),
  backward-compatible, and the store/API follow existing patterns
  exactly. The reviewer caught three charter violations in
  `delete_starter_gpo` (no optimistic concurrency, query params
  instead of body, discarded audit info) which were all fixed.
- The settings browser UI — follows existing patterns, ARIA-compliant,
  properly scoped filter handlers.

**Less confident in:**
- The legacy ADM parser (`adm.py`) — it handles common patterns but
  the .adm format is complex and underspecified. The parser is
  resilient (skips unparseable sections with warnings) but may miss
  edge cases in real-world .adm files. Needs testing against actual
  legacy .adm files from production environments.
- The bulk state change UI — the sequential API calls (one per side
  group) work but could be slow for large selections. A true bulk
  endpoint that handles multiple policy IDs in one request would be
  better, but the current API already does that — the frontend just
  splits by side unnecessarily.
- The copy-settings endpoint uses `put_settings` which merges by ID.
  This is correct behavior but could surprise users who expect a
  full replace. The UI doesn't make the merge semantics clear.

**The adversarial review process was valuable but imperfect:**
- Tranche 1 (kimi): caught the real export.py/validator issue.
- Tranche 3 (nemotron): prefix collision was a false positive (the
  `-` delimiter prevents it), ValidationError handling was already
  correct via global exception handler. But the review forced
  verification, which is valuable.
- Tranche 4 (glm): caught three real charter violations in
  delete_starter_gpo. This was the most productive review.

## Gaps to flag

- `src/gpo_studio/adm.py` — the parser handles common .adm patterns
  but hasn't been tested against real-world legacy .adm files. Edge
  cases in ACTIONLIST, complex PART types, and nested categories may
  not be handled correctly.
- `src/gpo_studio/static/js/browser.mjs:185` — the bulk action UI makes
  sequential API calls grouped by side. If the first call succeeds but
  a subsequent one fails, the GPO is left in a partially-updated state.
  The revision is updated between calls, but a transactional bulk
  endpoint would be safer.
- `src/gpo_studio/store.py:564` — `delete_starter_gpo` still doesn't
  create an audit revision before deleting (the GPO and all revisions
  are hard-deleted via cascade). The charter says "every mutation
  creates an immutable revision" — GPO deletion is a special case,
  but it's worth noting that the audit trail is destroyed.
- `tests/test_adm.py` — the ADM parser tests use synthetic .adm content.
  No test uses a real .adm file from a production environment.
- `src/gpo_studio/static/js/starter.mjs` — the Starter GPO list dialog
  doesn't refresh when a Starter GPO is created/deleted from another
  tab. The user must close and reopen the dialog.
- Prior session work (template_store.py classification, provenance.py,
  scripts/) is uncommitted and was not reviewed in this session. It
  needs its own review pass before merging.
- `src/gpo_studio/api.py` — the `configured_settings` endpoint response
  now includes `ambiguous` and `ambiguous_with` fields, but there's no
  OpenAPI/schema documentation for these new fields.
